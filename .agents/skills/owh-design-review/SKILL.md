# Design Review

Ground recommendations in current code/tests, the applicable instructions, owner docs, and accepted root ADRs. Distinguish implemented behavior, accepted decisions, and proposals.

Choose the requested outcome:
- Challenge a supplied plan: read [plan-review.md](references/plan-review.md).
- Find architectural opportunities: read [architecture.md](references/architecture.md), [LANGUAGE.md](LANGUAGE.md), and [DEEPENING.md](DEEPENING.md).
- Design a selected or explicitly requested interface: read [INTERFACE-DESIGN.md](INTERFACE-DESIGN.md).

Give concrete evidence, the smallest useful alternatives, and a recommendation. Ask only for unresolved consequential decisions; an already specified target does not require another selection round.
Use [ADR-FORMAT.md](ADR-FORMAT.md) only when an enduring decision needs rationale. Documentation edits follow the user's requested scope.
