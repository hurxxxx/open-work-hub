# 08. 화면 설계와 와이어프레임

> **한 줄 요약.** 화면 설계는 "예쁘게 그리는 일" 이 아니라 **"한 화면에 무엇이 들어갈지를 결정하는 일"** 이다. 색·폰트는 다음 단계, 지금은 회색 사각형으로 충분하다.

---

## 들어가며

기획이 끝났다면 이제 우리는 한 줄짜리 가치 제안과 한 명의 페르소나, 그리고 1개의 핵심 기능을 손에 들고 있습니다. 다음 단계는 그 모든 것을 **눈에 보이는 형태** 로 옮기는 일입니다. 그 첫 작업이 화면 설계입니다.

처음 만드는 분들이 자주 하는 실수가 두 가지 있습니다.

- **너무 일찍 예쁘게 만들려 한다** — 색·폰트·이미지에 시간을 쓰느라 정작 "이 화면에 무엇이 들어가야 하는가" 를 못 결정한다.
- **머릿속으로만 그린다** — 종이에 옮기지 않은 화면은 다 지나서 보면 빠진 게 한가득.

화면 설계의 진짜 목적은 **결정을 명시화** 하는 것입니다. 어떤 정보를, 어떤 순서로, 어떤 동작과 함께 보여줄지. 이 결정이 끝나야 디자인·개발이 흐트러지지 않습니다.

이 레슨을 다 읽으면:

- 와이어프레임의 3단계(저-중-고 충실도)를 구분할 수 있다.
- 한 화면을 4영역으로 나누어 설계하는 절차를 안다.
- 사용자 흐름(user flow) 다이어그램을 그릴 수 있다.
- 화면 설계 도구를 자기 상황에 맞게 고를 수 있다.
- 빠지기 쉬운 함정(빈 상태·로딩·에러)을 미리 챙길 수 있다.

---

## 1. 핵심 개념 — 와이어프레임의 3단계

와이어프레임(wireframe)은 화면의 뼈대입니다. 색·이미지·디테일은 빼고, **무엇이 어디에 놓이는가** 만 표시합니다. 충실도(fidelity)에 따라 3단계로 나뉩니다.

### 1.1 저충실도(Low-fidelity) — 종이·연습장 그림

가장 가벼운 형태. 그림 실력은 상관없습니다. 사각형과 텍스트면 충분합니다.

```
┌─────────────────────────┐
│   로고          메뉴     │
├─────────────────────────┤
│                         │
│   [큰 검색창]            │
│                         │
│   인기 카페 리스트       │
│   ┌───┐ ┌───┐ ┌───┐    │
│   │카드│ │카드│ │카드│    │
│   └───┘ └───┘ └───┘    │
│                         │
└─────────────────────────┘
```

(우리 컨벤션상 박스 다이어그램은 한글에서 정렬이 깨지므로, 실제 종이에는 위와 비슷한 그림을 그리지만 본문 표현은 디렉토리 트리·표·목록을 권합니다.)

**언제 쓰나:** 첫 30분~1시간. 가능한 화면 후보를 빨리 펼쳐 보기. **버려도 아깝지 않은 형태** 라 생각이 자유롭습니다.

### 1.2 중충실도(Mid-fidelity) — 회색 박스 와이어프레임

저충실도를 정리해서 도구로 옮긴 형태. 색은 회색·흰색·검정만 씁니다.

이 단계에서 결정되는 것:

- 각 영역의 **상대적 크기**
- 요소들의 **순서·정렬**
- 화면 사이의 **이동 흐름** (버튼 누르면 어디로)

**언제 쓰나:** 1~2일. 디자이너·개발자와 합의를 시작하기에 적당한 단계.

### 1.3 고충실도(High-fidelity) — 실제 디자인

색·이미지·실제 데이터·인터랙션이 모두 들어간 형태. 거의 완성된 화면처럼 보입니다.

**언제 쓰나:** 디자이너의 작업물. 보통 중충실도 와이어프레임이 합의된 후. 이 단계는 다음 레슨([`12. 디자인 시스템과 비주얼 설계`](./12-디자인시스템.md)) 에서 다룹니다.

### 충실도 단계의 비교

| 단계 | 도구 | 시간 | 목적 |
|---|---|---|---|
| 저충실도 | 종이·연습장 | 30분~1시간 | 아이디어 펼치기 |
| 중충실도 | Figma·Whimsical·Balsamiq | 1~2일 | 합의·결정 명시화 |
| 고충실도 | Figma·Sketch | 며칠~몇 주 | 디자인 완성 |

처음 만드는 분이라면 **저 → 중** 까지만 해도 충분합니다. 고충실도는 디자이너가 있는 팀의 영역.

## 2. 실무 흐름 — 한 화면을 설계하는 4영역 절차

한 화면을 그릴 때 다음 4영역으로 나눠 결정하면 빠짐이 적습니다.

### 영역 1. 헤더 / 상단 (Top)

화면 맨 위. 보통 다음을 담습니다.

- 로고·서비스 이름
- 메뉴 버튼 (모바일은 햄버거 ☰)
- 검색·알림·프로필 아이콘
- 페이지 제목 (서브 페이지의 경우)

**결정할 것:**
- 페이지마다 헤더가 같은가, 다른가
- 스크롤 시 따라 내려오는가, 사라지는가

### 영역 2. 본문 / 중심 (Main)

화면의 중심. 여기에 핵심 콘텐츠가 들어갑니다.

- 핵심 기능의 입력·출력
- 리스트, 카드, 폼, 차트 등

**결정할 것:**
- 사용자가 이 화면에서 **가장 먼저 보길 원하는 한 가지**가 무엇인가
- 그 한 가지가 화면의 시각적 중심에 있는가
- 데이터가 없을 때 (빈 상태)·로딩 중일 때·에러일 때 어떻게 보일지

### 영역 3. 보조 / 사이드 (Side / Bottom)

본문 외의 보조 정보·동작.

- 필터·정렬 옵션
- 부가 정보 (광고·관련 콘텐츠)
- 모바일은 하단 네비게이션 바

**결정할 것:**
- 이 영역이 **정말 필요한가**. 없으면 본문이 더 단순해진다.

### 영역 4. CTA — Call to Action

사용자가 이 화면에서 **취해야 할 행동** 의 버튼.

- "회원가입", "구매하기", "다음", "저장" 등
- 한 화면에 보통 1개의 주된 CTA + 1~2개의 보조 CTA

**결정할 것:**
- CTA 버튼이 시각적으로 가장 두드러지는가
- 한 화면에 CTA가 너무 많지 않은가 (3개 이상이면 보통 너무 많음)
- 사용자가 그 CTA를 누른 다음 어디로 가는가

### 4영역 체크리스트

| 영역 | 질문 |
|---|---|
| 헤더 | 항상 같은 형태인가? 로고가 있나? |
| 본문 | 가장 먼저 보길 원하는 한 가지가 무엇인가? |
| 보조 | 정말 필요한가? 없으면 본문이 단순해지는가? |
| CTA | 한 화면에 1~2개인가? 시각적으로 두드러지는가? |

## 3. 사용자 흐름 (User Flow)

화면을 하나씩 잘 그렸어도, **화면 사이의 이동**이 흐려지면 사용자가 길을 잃습니다. 사용자 흐름은 화면 → 화면의 이동을 시각화하는 작업입니다.

### 3.1 흐름 다이어그램의 기본 형태

가장 단순한 형태는 화살표로 연결된 박스의 나열입니다.

```
[홈] → [검색] → [결과 리스트] → [상세] → [예약]
                      ↓
                 [필터·정렬]
```

각 화살표는 사용자의 한 동작에 대응합니다. "검색어 입력 후 엔터" → "결과 리스트로 이동" 같은 식.

### 3.2 분기 처리

흐름은 직선이 아닙니다. 사용자의 선택·상태에 따라 다른 길로 갑니다.

```
[홈]
  ├─ (로그인됨) → [개인화 추천]
  └─ (로그인 안됨) → [로그인 화면] → [홈]
```

분기점에서 **각 경로마다 별도 화면을 만들어야 하는지** 결정합니다.

### 3.3 결정적 순간 표시

레슨 07에서 다룬 "결정적 순간" 을 흐름 다이어그램에 표시해 두면, 그 순간으로 가는 길이 짧은지 점검할 수 있습니다.

```
[홈] → [검색] → [결과] → [상세] ★ → [예약]
                            └ 결정적 순간
```

★ 표시까지의 클릭 수가 4번. 이 숫자가 작을수록 좋습니다.

### 3.4 흐름 다이어그램 도구

| 도구 | 적합한 상황 |
|---|---|
| 종이·화이트보드 | 처음 30분~1시간 |
| Whimsical, Miro, FigJam | 합의·공유 |
| Figma의 Auto-flow 플러그인 | 와이어프레임과 같이 |
| draw.io, Excalidraw | 무료, 간단함 |

## 4. 빠지기 쉬운 화면 — 빈 상태·로딩·에러

처음 화면을 설계할 때 가장 자주 빠뜨리는 것이 **"성공이 아닌 상태"** 입니다. 화면을 그릴 때 항상 다음 4가지 상태를 모두 그려야 합니다.

### 상태 1. 정상 상태

데이터가 충분히 있고, 사용자가 기대한 콘텐츠가 보임. 보통 이 상태만 그려집니다.

### 상태 2. 빈 상태 (Empty state)

데이터가 없을 때. 출시 직후 거의 모든 화면이 이 상태입니다.

- 가입 직후 첫 방문 → 친구 0명, 게시글 0개.
- 검색 결과 없음.
- 알림 없음.

**잘 만든 빈 상태:**
- 왜 비어 있는지 한 줄 설명.
- 다음에 무엇을 하면 좋은지 안내.
- 가능하면 짧은 일러스트·아이콘.

```
┌─────────────────────────┐
│                         │
│      ✨ (아이콘)         │
│                         │
│   아직 친구가 없어요     │
│                         │
│   친구를 초대해 보세요   │
│                         │
│   [초대 코드 보내기]      │
│                         │
└─────────────────────────┘
```

### 상태 3. 로딩 상태

데이터를 가져오는 중. 사용자에게 "기다리고 있구나" 를 알려야 합니다.

- 스피너 (작은 회전 아이콘).
- 스켈레톤 UI (콘텐츠 모양의 회색 자리).
- 진행 바 (긴 작업의 경우).

로딩이 1초 이내라면 스피너로 충분합니다. 3초 이상이라면 스켈레톤 UI 또는 진행 표시가 필요합니다.

### 상태 4. 에러 상태

서버 오류, 네트워크 끊김, 권한 부족 등.

**잘 만든 에러 상태:**
- 무엇이 잘못됐는지 한 줄 설명 (기술 용어 빼고).
- 사용자가 할 수 있는 다음 행동 ("다시 시도", "문의하기").
- 에러 코드는 작게.

```
"일시적으로 문제가 발생했어요. 잠시 후 다시 시도해 주세요."
[다시 시도]   [문의하기]
```

### 4상태 매트릭스

| 화면 | 정상 | 빈 상태 | 로딩 | 에러 |
|---|:-:|:-:|:-:|:-:|
| 홈 | ✓ | ✓ | ✓ | ✓ |
| 리스트 | ✓ | ✓ | ✓ | ✓ |
| 검색 결과 | ✓ | ✓ | ✓ | ✓ |
| 상세 | ✓ | — | ✓ | ✓ |
| 폼 (입력 화면) | ✓ | — | — | ✓ (제출 실패) |

각 화면마다 이 4상태가 정의되어 있는지 점검하세요.

## 5. 와이어프레임 도구 가이드

처음 만드는 분이 고민할 만한 도구들을 짧게 비교합니다.

### 도구 비교

| 도구 | 충실도 | 학습 곡선 | 가격 | 적합한 상황 |
|---|---|---|---|---|
| **종이·연습장** | 저 | 0 | 무료 | 처음 30분 |
| **Excalidraw** | 저~중 | 매우 낮음 | 무료 | 가벼운 와이어프레임 |
| **Whimsical** | 중 | 낮음 | 부분 무료 | 흐름·와이어프레임 같이 |
| **Balsamiq** | 중 | 낮음 | 유료 | 회색 박스 와이어프레임 전문 |
| **Figma** | 저~고 | 중간 | 부분 무료 | 본격 디자인까지 가는 길 |
| **Sketch** | 고 | 중간 | 유료 (Mac) | 디자이너 전용 |

처음 만드는 분이라면 **종이 → Excalidraw 또는 Whimsical → Figma** 순이 자연스럽습니다. Figma는 다음 레슨(디자인 시스템)에서 본격적으로 쓰게 됩니다.

### Figma 입문의 최소 단위

Figma를 처음 쓴다면 다음 5개 기능만 알면 와이어프레임은 만들 수 있습니다.

1. **Frame** — 화면 한 장의 캔버스.
2. **Rectangle / Text** — 사각형과 텍스트로 영역 표현.
3. **Auto Layout** — 요소들을 자동 정렬.
4. **Component** — 반복 요소 (버튼·카드)를 재사용.
5. **Prototype** — 화면들을 화살표로 연결해 흐름 시뮬레이션.

이 5가지로 중충실도 와이어프레임은 충분합니다.

## 6. 자주 빠지는 함정

### 함정 1. 너무 일찍 예쁘게 만든다

색·폰트·이미지에 첫날부터 시간을 쓰면 정작 "무엇이 들어가야 하는가" 를 못 결정합니다. **색·폰트는 의도적으로 회색·검정·흰색만** 쓰세요. 결정이 끝난 후에 색을 입혀도 늦지 않습니다.

### 함정 2. 머릿속으로만 그린다

종이에 안 옮긴 화면은 항상 빠진 게 있습니다. **30분이라도 종이에 그려 보세요.** 그리면서 "어, 여기 빈 상태는 뭐지?" 같은 질문이 자동으로 나옵니다.

### 함정 3. 빈 상태·로딩·에러를 안 그린다

위 4상태 중 정상 상태만 그리면 출시 후 빈 상태에서 사용자가 길을 잃습니다. **첫 방문이 곧 빈 상태** 라는 사실을 잊지 마세요.

### 함정 4. CTA가 너무 많다

한 화면에 "구독하기", "공유하기", "친구 초대", "리뷰 남기기" 같은 버튼이 5개 있으면 사용자는 어떤 것도 누르지 않습니다. **한 화면에 주된 CTA 1개**, 보조 1~2개로 줄이세요.

### 함정 5. 모든 화면을 다 그리려 한다

서비스 전체에 화면이 30~50개라면 모두 와이어프레임으로 그리는 데 며칠이 걸립니다. **결정적 순간이 있는 5~7개 화면**부터 그리세요. 나머지는 개발 중 그려도 늦지 않습니다.

### 함정 6. 모바일·PC를 따로 그리지 않는다

반응형이라고 하지만, 모바일과 PC는 보이는 모양이 다릅니다. **모바일을 먼저** 그리고 PC를 그리세요. 모바일이 더 좁아서 우선순위 결정이 더 분명해집니다.

### 함정 7. 사용자 흐름 없이 화면만 그린다

화면 5개를 잘 그렸어도 화면 사이 이동이 흐리면 흐름이 깨집니다. **흐름 다이어그램 한 장**을 따로 그려, 화면들이 어떻게 이어지는지 표시하세요.

---

## 7. 한 셜 더

### 7.1 모바일 우선 (Mobile First)

대부분의 서비스에서 모바일 사용자가 PC보다 많습니다. 그래서 와이어프레임도 모바일을 먼저 그리는 것이 자연스럽습니다. 모바일 화면에서 결정한 우선순위가 PC에 반영되면, PC에서 화면이 비좁지 않으면서도 핵심이 분명해집니다.

거꾸로 PC를 먼저 그리고 모바일로 줄이려 하면, 무엇을 빼야 할지 결정 못 해 모바일 화면이 답답해집니다.

### 7.2 정보 구조 (Information Architecture, IA)

화면 설계 전에 또는 함께 진행하면 좋은 작업이 **정보 구조 설계** 입니다. 서비스의 전체 페이지·메뉴를 트리 형태로 정리합니다.

```
홈
├─ 검색
│  ├─ 카페 검색
│  └─ 사용자 검색
├─ 즐겨찾기
└─ 마이페이지
   ├─ 내 리뷰
   ├─ 설정
   └─ 로그아웃
```

이 트리가 명확하면 사용자가 어디서 무엇을 찾을지 헷갈리지 않습니다. 페이지 수가 5개 이상이라면 한 번 그려 보세요.

### 7.3 디자인 패턴 라이브러리

흔히 쓰이는 화면 패턴들이 있습니다. 처음부터 새로 발명하지 말고 검증된 패턴을 가져다 쓰세요.

- **Mobbin** (mobbin.com) — 실제 앱들의 화면 캡처 모음.
- **Nicely Done** (nicelydone.club) — 우수 사례 모음.
- **Page Flows** (pageflows.com) — 사용자 흐름 사례 모음.

다른 앱이 어떻게 풀었는지 보면 자기 화면이 빨리 정리됩니다. 모방이 아니라 **학습**의 도구입니다.

### 7.4 추가 키워드

- **Information Architecture (IA)** — 서비스 전체의 정보 구조.
- **F-Pattern / Z-Pattern** — 사용자가 화면을 읽는 시선의 흐름.
- **Heuristic Evaluation** — 화면을 휴리스틱(Nielsen의 10원칙)으로 점검.
- **Affinity Mapping** — 사용자 인터뷰 내용을 그룹핑해 화면에 반영.

## 마치며

오늘 한 일:

- 와이어프레임의 **3단계 충실도** (저·중·고) 와 각 단계의 목적.
- 한 화면을 **4영역**(헤더·본문·보조·CTA)으로 나눠 설계하는 절차.
- **사용자 흐름** 다이어그램으로 화면 사이 이동을 시각화.
- 빠뜨리기 쉬운 **4상태**(정상·빈·로딩·에러) 설계.
- 도구 비교(종이~Figma)와 처음 만드는 분이 갈 만한 길.
