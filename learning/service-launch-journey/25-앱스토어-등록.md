# 25. 앱스토어·구글플레이 등록과 심사

> **한 줄 요약.** 앱 스토어 등록은 **앱 자체보다 메타데이터·정책 준수·결제 연동**이 더 시간을 잡아먹는다. 첫 심사는 거의 항상 한 번 거절(reject)된다 — 미리 마음의 준비.

---

## 들어가며

웹 서비스만 만든다면 출시는 도메인 연결로 끝납니다. 그런데 모바일 앱이라면 이야기가 다릅니다. **앱 스토어 (Apple App Store)** 와 **구글 플레이 (Google Play Store)** 라는 관문을 통과해야 사용자에게 도달합니다.

처음 만드는 분이 이 관문에서 자주 막히는 자리:

- 등록 절차가 어디서 시작되는지 모름.
- 심사가 며칠 걸리는지, 거절되면 어떻게 해야 하는지 막막.
- iOS 의 In-App Purchase 강제 정책이 뭔지 모름.
- 스크린샷·설명·아이콘 같은 메타데이터에 시간이 더 들 수 있음.

이 레슨은 두 스토어의 등록 절차를 정리하고, 첫 심사를 통과하는 데 필요한 준비를 챙깁니다.

이 레슨을 다 읽으면:

- 앱 스토어와 구글 플레이의 차이를 안다.
- 등록에 필요한 자료 체크리스트를 갖춘다.
- 심사 정책의 흔한 거절 사유를 안다.
- 결제 정책(IAP·외부 결제) 의 트레이드오프를 안다.
- 첫 출시 후 업데이트·베타 테스트 흐름을 안다.

---

## 1. 두 스토어의 큰 차이

### 1.1 비교 표

| 항목 | App Store (iOS) | Google Play (Android) |
|---|---|---|
| 개발자 등록비 | $99 / 년 | $25 (1회) |
| 심사 기간 | 24시간~1주 | 몇 시간~며칠 |
| 심사 엄격도 | 매우 엄격 | 중간 |
| 정책 변경 빈도 | 자주 | 보통 |
| 결제 강제 | IAP 강제 (외부 결제 제한) | IAP 강제, 일부 우회 가능 |
| 거절 후 재제출 | 빠름 (보통 1~2일) | 빠름 |
| 사용자 비중 (한국) | 30~40% | 60~70% |

### 1.2 Apple 이 더 까다로운 이유

- 심사관이 직접 앱을 사용해 봄 (구글은 더 자동화).
- 가이드라인이 광범위 ("사용자 경험을 해친다고 판단되면" 같은).
- 정책 위반 시 사후 추방도 자주.

처음 출시 시 시간을 더 들이는 쪽은 거의 항상 iOS.

## 2. 개발자 등록

### 2.1 Apple Developer Program

- 비용: **$99 / 년**.
- 가입: developer.apple.com.
- 절차: 본인 인증, 결제, 약관.
- 개인 vs 회사: 회사로 등록하려면 D-U-N-S 번호 (며칠 추가 소요).

회사로 등록하면 앱 스토어에 회사명이 표시. 개인으로 등록하면 개인 이름.

### 2.2 Google Play Developer

- 비용: **$25 (1회)**.
- 가입: play.google.com/console.
- 절차: 본인 인증, 결제, 약관.
- 신분증 검증·D-U-N-S 검증 등이 추가될 수 있음 (2024~2025 정책 강화).

### 2.3 한국 사업자

부가세 신고를 위해 사업자 정보 등록. 개인 사업자도 가능.

## 3. 등록 자료 체크리스트

심사 신청 전에 준비할 자료들. 의외로 시간이 많이 걸립니다.

### 3.1 앱 자체

| 항목 | 비고 |
|---|---|
| 빌드된 앱 (.ipa·.aab) | 레슨 21 의 산출물 |
| 버전 번호 | `1.0.0` 같은 |
| 빌드 번호 | iOS 는 별도 증가 번호 |

### 3.2 비주얼 메타데이터

| 항목 | iOS 요구 | Android 요구 |
|---|---|---|
| **앱 아이콘** | 1024×1024 (스토어용), 다양한 크기 (앱 내장) | 512×512 |
| **스크린샷** | iPhone (6.5"·5.5") 각 3장 이상 | 휴대폰·태블릿 각 2~8장 |
| **앱 미리보기 영상** | 선택, 30초 이내 | 선택, 30초 이내 |
| **피처 그래픽** | — | 1024×500 (Play 메인 진열용) |

스크린샷은 그냥 화면 캡처보다 **카피와 함께 디자인된 이미지**가 일반적. Figma·App Mockup 도구 활용.

### 3.3 텍스트 메타데이터

| 항목 | 기능 |
|---|---|
| **앱 이름** | 30자 이내. 검색 키워드 영향 큼 |
| **부제 (Subtitle)** | iOS 30자. 핵심 가치 한 줄 |
| **짧은 설명 (Short Description)** | Android 80자. 카드 미리보기 |
| **상세 설명** | 4000자. 기능·특징 |
| **키워드** | iOS 100자. 검색 노출 |
| **카테고리** | 1차·2차 카테고리 |
| **연령 등급** | 폭력·언어 등 자가 신고 |

ASO (App Store Optimization) — 검색 노출을 위한 메타데이터 최적화. 첫 출시 후 데이터 보고 점진 개선.

### 3.4 정책·법률

| 항목 | 무엇 |
|---|---|
| **개인정보 처리방침** (Privacy Policy) | 필수. 별도 URL 호스팅 |
| **이용약관** (Terms of Service) | 권장 |
| **데이터 수집 항목 신고** | 어떤 데이터를 수집하는지 자가 신고 |
| **연락처 (Support URL·Email)** | 사용자 문의용 |

개인정보 처리방침 누락은 가장 흔한 거절 사유. 무료 생성 도구도 많지만 **자기 서비스에 맞게 수정** 필수.

### 3.5 심사용 정보

| 항목 | 무엇 |
|---|---|
| **심사용 계정** | 로그인이 필요한 앱이라면 테스트 계정 제공 |
| **심사 노트** | 심사관에게 설명 필요한 부분 (테스트 방법 등) |
| **데모 영상** (선택) | 복잡한 기능의 사용 방법 |

심사관이 로그인을 못 하면 즉시 거절. 테스트 계정·결제 우회 코드 등을 명확히 제공.

## 4. 심사 — 흔한 거절 사유

### 4.1 iOS 의 흔한 거절

**1. 메타데이터 거절** (Metadata Rejected)
- 스크린샷이 실제 앱과 다름.
- 설명에 다른 플랫폼 언급 ("Android 에서도 사용 가능").
- 키워드 남용·경쟁사 이름.

**2. 기능 부족** (Minimum Functionality)
- 단순 웹뷰 래퍼로 보이면 거절. 네이티브 기능·가치 추가 필요.
- "앱이 너무 단순해서 웹사이트로 충분" 이라 판단.

**3. 결제 가이드라인** (3.1.1)
- 디지털 콘텐츠 결제는 IAP 강제.
- 외부 결제 링크 노출 금지.
- "구독" 으로 표기 시 자동 갱신 명시.

**4. 개인정보·로그인** (5.1.1)
- 로그인이 필요한 이유가 분명해야.
- 비회원 모드 권장.
- "Apple 로 로그인" 옵션 강제 (다른 소셜 로그인 제공 시).

**5. 광고 SDK·추적**
- App Tracking Transparency (ATT) 동의 안 받음.
- 광고 ID 사용 신고 누락.

**6. 디자인 가이드라인 위반**
- iOS HIG 와 너무 다른 UI.
- 안드로이드 스타일 컴포넌트.

### 4.2 Android 의 흔한 거절

**1. 권한 남용**
- 필요 없는 권한 요청 (위치·연락처 등).
- 권한 사용 이유를 명시 안 함.

**2. 정책 위반 콘텐츠**
- 폭력·성적 콘텐츠.
- 잘못된 의료·금융 정보.
- 사용자 데이터 무단 사용.

**3. 14세 미만 데이터**
- 어린이 대상이면 추가 정책 (DSA·COPPA).

**4. APK / AAB 문제**
- 패키지명 충돌.
- 서명 키 문제.
- 64비트 미지원.

### 4.3 거절되면

**침착하게 대응:**

1. 거절 메시지를 정확히 읽기.
2. 어느 가이드라인의 어느 항목인지 확인.
3. 수정.
4. 재제출 + Resolution Center 에 응답 (iOS).

심사관과 직접 메시지 교환 가능 (Resolution Center). 이의 제기 가능. 정중하고 사실 기반으로.

처음 출시 시 평균 **1~2회 거절** 후 통과가 흔합니다. 의기소침하지 마세요.

## 5. 결제 정책 — IAP 의 함정

### 5.1 IAP 강제 정책

**Apple:**
- 디지털 콘텐츠·구독은 In-App Purchase 강제.
- 수수료 30% (소규모 개발자 15%, 두 번째 해 구독 15%).
- 외부 결제 링크 사실상 불가.

**Google:**
- 비슷하게 IAP 강제.
- 한국에서는 외부 결제 일부 허용 (2022 한국 법 개정).

### 5.2 IAP 가 강제 안 되는 경우

- **물리 상품·서비스** (배달·교통·예약).
- **B2B SaaS**.
- **광고 기반** (광고 노출 자체는 IAP 아님).

내가 만들 서비스가 어디에 해당하는지 미리 확인.

### 5.3 IAP 통합

iOS:
- StoreKit·StoreKit 2.
- App Store Connect 에서 상품 설정.
- 영수증 검증 백엔드 필요.

Android:
- Google Play Billing Library.
- Google Play Console 에서 상품 설정.
- 라이선스 검증 백엔드.

크로스 플랫폼:
- RevenueCat — 두 플랫폼 통합 SDK + 분석. 강력 권장.

### 5.4 가격 책정

- 두 스토어 모두 **티어** 제도 (Apple Tier 1·2·3 …).
- 환율 자동 변환되지만 국가별 한국 시장가 별도 설정 가능.
- 무료 체험 (Free Trial)·할인 제공 가능.

## 6. 첫 출시 절차 — 단계별

### 6.1 앱 빌드

레슨 21 참고. 산출물:
- iOS: `.ipa` 또는 Xcode Archive.
- Android: `.aab` (Android App Bundle).

### 6.2 스토어 등록 페이지 작성

- 메타데이터 + 비주얼 + 정책 모두 입력.
- 미리보기 신중히.

### 6.3 빌드 업로드

- iOS: Xcode·Transporter·`xcrun altool`.
- Android: Play Console 직접 업로드 또는 fastlane.

### 6.4 심사 제출

- 테스트 계정·심사 노트 첨부.
- 출시일 설정 (즉시 또는 예약).

### 6.5 심사 결과 대기

- iOS: 평균 24~48시간.
- Android: 몇 시간~며칠.
- 거절 시 수정·재제출.

### 6.6 출시

- 통과 시 자동 출시 (또는 수동 승인 후).
- 한 번에 모든 국가 vs 일부 국가 단계적.

## 7. 베타 테스트

### 7.1 iOS — TestFlight

- App Store Connect → TestFlight.
- 내부 테스터 100명 + 외부 테스터 10,000명.
- 이메일 초대.
- 90일 후 테스트 빌드 만료.

### 7.2 Android — Play Console

- 내부 테스트: 100명, 즉시 (심사 없음).
- 비공개 테스트: 명단 기반.
- 공개 테스트 (오픈 베타): 누구나.

### 7.3 점진 출시 (Staged Rollout)

처음에 1% 사용자에게만, 문제 없으면 점진 확대. 두 스토어 모두 지원.

새 버전이 깨지면 영향 범위 최소화.

## 8. 자주 빠지는 함정

### 함정 1. "출시 다음 주" 일정으로 마지막에 시작

심사 + 거절 + 재심사 합치면 1~2주 흔히 걸림. **출시 예정일 2주 전에는** 첫 제출.

### 함정 2. 개인정보 처리방침 빠뜨림

가장 흔한 거절. 별도 URL 에 호스팅 + 스토어에 링크.

### 함정 3. 메타데이터를 가볍게

스크린샷·설명에 시간을 들이세요. 다운로드율을 좌우합니다.

### 함정 4. 심사관이 로그인 못 함

테스트 계정 제공 필수. 만료된 계정 안 됨.

### 함정 5. 외부 결제 링크 노출

iOS 에서 거의 즉시 거절. 디지털 결제는 IAP.

### 함정 6. 단순 웹뷰

웹사이트를 그대로 감싼 앱은 iOS 에서 거절. 네이티브 기능(푸시·오프라인·카메라 등) 활용.

### 함정 7. "Apple로 로그인" 누락

다른 소셜 로그인이 있으면 Apple Sign In 도 의무 (iOS).

### 함정 8. 권한 사용 이유 누락

`Info.plist`·`AndroidManifest.xml` 에 권한 사용 이유 작성. 빠뜨리면 거절.

### 함정 9. 베타·운영 빌드를 동시에 안 굴림

베타 빌드만 있고 운영 빌드는 따로 안 만듦. 올바른 워크플로 정립.

### 함정 10. 첫 거절에 좌절

거의 모두가 한 번씩 거절 받습니다. 침착하게 수정·재제출.

## 9. 한 셜 더

### 9.1 ASO — App Store Optimization

검색·발견 노출을 위한 최적화.

- 키워드 연구 (Mobile Action·App Annie).
- 제목·부제 키워드 배치.
- 스크린샷·미리보기 영상 A/B 테스트 (iOS A/B 기능).
- 리뷰·평점 관리.

### 9.2 빌드 자동화 — fastlane

iOS·Android 의 빌드·서명·업로드를 명령 한 줄로.

```ruby
# fastfile
lane :release do
  build_ios_app
  upload_to_app_store
end
```

CI 에 통합하면 PR 머지 → 자동 베타 빌드 업로드.

### 9.3 코드 사이닝

- iOS: 인증서·프로비저닝 프로파일·디바이스 UDID. 복잡함. fastlane match 가 자동.
- Android: keystore 파일 + Play App Signing.

### 9.4 인앱 업데이트

- iOS: App Store 의 자동 업데이트.
- Android: in-app updates API 로 강제·권장 업데이트.

### 9.5 추가 키워드

- **Universal Link / App Link** — 웹 URL 클릭 시 앱 열기 (레슨 24).
- **Custom URL Scheme** — `myapp://` 형태의 앱 전용 URL.
- **Smart Banner** — 웹사이트에서 앱 다운로드 권장 배너.
- **Dynamic Links** (Firebase) — 앱 미설치 시 스토어로, 설치 후 특정 화면으로.
- **Apple Search Ads / UAC** — 앱 광고.
