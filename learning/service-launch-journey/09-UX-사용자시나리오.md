# 09. UX·사용자 시나리오

> **한 줄 요약.** UX 설계는 한 화면이 아니라 **여러 화면이 시간 순으로 엮인 이야기**다. 시나리오를 글로 써 봐야 빠진 화면이 보인다.

---

## 들어가며

화면 설계가 "한 장면" 이라면, 시나리오는 "한 편의 영화" 입니다. 한 사용자가 우리 서비스를 처음 만나서 가치를 받기까지, 어떤 화면을 어떤 순서로 거치는지를 시간 축으로 적는 작업입니다.

이 작업이 빠지면 자주 일어나는 일이 있습니다.

- 화면 한 장씩은 잘 그려졌는데, 합쳐 놓고 보니 **사이의 다리가 빠짐**.
- 가입 → 첫 사용까지 가는 길에 **5번의 클릭**이 필요한데, 페르소나가 그 사이에 이탈.
- 어드민·비로그인 사용자 같은 **다른 시나리오**를 잊었다가 출시 후 깨짐.

이 레슨은 화면들을 시간 축으로 엮어 **한 편의 이야기로 만들고**, 그 이야기에서 막히는 자리를 미리 발견하는 절차입니다.

이 레슨을 다 읽으면:

- 사용자 시나리오의 표준 형식(상황·동작·결과)을 안다.
- Happy Path / Edge Case / 비로그인 / 어드민 시나리오를 구분할 수 있다.
- 시나리오에서 결정적 순간까지의 클릭 수를 줄이는 방법을 안다.
- 사용자 여정 지도(Customer Journey Map)를 그릴 수 있다.

---

## 1. 핵심 개념 — 시나리오는 글이다

### 1.1 시나리오 = 사용자가 겪는 한 편의 이야기

좋은 시나리오는 **읽으면 영화가 머릿속에 그려지는** 글입니다. 누가, 언제, 어디서, 무슨 동기로, 어떤 화면을 거쳐, 어떤 결과를 얻는지가 모두 들어 있어야 합니다.

예시 — 부부 가계부 앱:

> 김지영(32세, 결혼 1년차 워킹맘)은 어제 친구 카톡방에서 "○○ 가계부 앱 좋대" 라는 추천을 봤다. 오늘 아침 출근길 지하철에서 그 단어가 떠올라 앱스토어에서 검색한다. 첫 번째 결과를 다운로드. 앱을 열면 "둘이 같이 보는 가계부" 한 줄이 보인다. 가입 화면에서 카카오로 한 번에 가입 완료. 첫 화면에 "남편을 초대하세요" 버튼이 큼지막하게 보인다. 초대 코드를 복사해 남편에게 카톡으로 보낸다. 점심에 남편이 가입하고, 저녁에 둘의 카드 거래가 한 화면에 모두 떠 있는 것을 본다. "오, 이거 됐네." — 만족.

이 시나리오를 읽으면 다음이 보입니다.

- 첫 화면의 가치 제안 ("둘이 같이 보는 가계부").
- 가입의 장벽 (카카오 로그인 1번 클릭).
- 핵심 동작 (남편 초대 → 카드 자동 인식).
- 결정적 순간 (저녁 시간, 둘의 거래가 한 화면에 떠 있는 모습).

각 문장이 한 화면 또는 한 동작에 대응합니다. 화면이 빠지면 글이 어색해집니다.

### 1.2 시나리오와 화면 설계의 관계

시나리오와 화면 설계는 서로 보완합니다.

| 작업 | 무엇을 결정 |
|---|---|
| 화면 설계 | 한 화면 안에 무엇이 들어갈지 |
| 시나리오 | 화면들이 어떤 순서로 이어질지 |

화면 설계만 있으면 "각 화면은 OK인데 흐름이 끊기는" 서비스가 됩니다. 시나리오만 있으면 "흐름은 좋지만 각 화면이 비어 있는" 서비스가 됩니다. 둘이 같이 가야 합니다.

## 2. 실무 흐름 — 시나리오 작성 4단계

### 단계 1. 시나리오 종류 정하기

한 서비스에는 여러 종류의 시나리오가 있습니다. 출시 전에 다음을 모두 정의해야 합니다.

| 종류 | 예시 |
|---|---|
| **Happy Path** | 핵심 페르소나가 핵심 가치를 받는 가장 일반적 경로 |
| **신규 가입 시나리오** | 가입부터 첫 가치 경험까지 |
| **재방문 시나리오** | 두 번째·세 번째 방문에서 무엇을 보고 무엇을 하는가 |
| **이탈 회복 시나리오** | 사용자가 한동안 안 들어왔다가 다시 들어왔을 때 |
| **비로그인 시나리오** | 가입 안 한 방문자가 보는 화면 |
| **어드민 시나리오** | 운영자가 콘텐츠·사용자를 관리하는 흐름 |
| **에러 시나리오** | 결제 실패, 네트워크 끊김, 서버 다운 등 |

처음 출시할 때 모두 다 갖출 필요는 없지만, 적어도 **Happy Path + 신규 가입 + 비로그인** 세 가지는 명시적으로 작성해야 합니다.

### 단계 2. 시나리오 한 편 글로 쓰기

시나리오의 표준 구조:

```
[사용자] 가 [상황] 에서 [동기] 를 가지고 우리 서비스에 들어온다.
1. 첫 화면에서 [본 것].
2. [한 동작] 을 한다.
3. [그 결과 화면] 에서 [본 것].
4. ...
N. [결정적 순간 — 가치를 받는 지점].
N+1. [그 후의 행동·감정].
```

각 번호가 한 화면 또는 한 동작입니다. 글로 적으면서 다음을 자문합니다.

- 이 화면에서 사용자가 다음 행동을 알아챌 수 있는가
- 이 동작에 몇 번의 탭·클릭이 필요한가
- 사용자가 이 단계에서 이탈할 만한 이유가 있는가

### 단계 3. 클릭 수 세기

시나리오를 다 적었다면 **시작에서 결정적 순간까지의 동작 수**를 셉니다.

| 시나리오 | 동작 수 | 평가 |
|---|---:|---|
| 가입 → 친구 초대 → 첫 거래 인식 → 정산 화면 | 6번 | 적당 |
| 가입 → 카드 등록 → 카테고리 설정 → ... → 정산 화면 | 12번 | 너무 많음 |

동작 수가 많으면 그 사이에서 사용자가 이탈합니다. **결정적 순간까지의 동작이 5번 이내**가 되도록 줄이세요. 줄이는 방법:

- 가입을 소셜 로그인으로 (1번에 끝).
- 카테고리·설정을 자동 또는 나중으로 미루기.
- 첫 화면에서 핵심 가치를 즉시 보여주기.

### 단계 4. 다른 시나리오로 한 번 더

Happy Path가 끝났다면 비로그인·어드민·에러 시나리오도 같은 방식으로. 각 시나리오마다 빠진 화면이 새로 발견됩니다.

예시 — 비로그인 시나리오에서 발견되는 화면:

- 비로그인으로 들어왔을 때 첫 화면
- 가입 유도 모달
- 일부 기능을 가입 없이 미리 체험할 수 있는 영역

이 화면들이 처음 화면 설계에는 빠져 있을 가능성이 큽니다. 시나리오로 발견해서 추가합니다.

## 3. 사용자 여정 지도 (Customer Journey Map)

시나리오를 시각화하는 가장 흔한 도구가 **사용자 여정 지도** 입니다. 시간 축으로 사용자의 단계·생각·감정·접점을 한 표에 정리합니다.

### 3.1 표준 형식

| 축 | 무엇 |
|---|---|
| **단계 (Phase)** | 발견 → 탐색 → 가입 → 첫 사용 → 재방문 → 추천 |
| **사용자 행동** | 각 단계에서 무엇을 하는가 |
| **사용자 생각** | 머릿속으로 무엇을 떠올리는가 |
| **사용자 감정** | 어떤 감정인가 (😀 / 😐 / 😟) |
| **접점** | 어느 화면·기능을 거치는가 |
| **기회** | 우리가 개선할 자리 |

### 3.2 부부 가계부 앱 예시

| 단계 | 행동 | 생각 | 감정 | 접점 | 기회 |
|---|---|---|---|:-:|---|
| 발견 | 친구가 추천 | "괜찮을까?" | 😐 | 카톡 메시지 | 추천 플로우 강화 |
| 탐색 | 앱스토어 검색 | "리뷰 보자" | 😐 | 앱스토어 페이지 | 스크린샷·리뷰 정리 |
| 가입 | 카카오 로그인 | "빨리 끝났네" | 😀 | 가입 화면 | 1탭 가입 유지 |
| 초대 | 남편에게 코드 전송 | "남편이 가입할까?" | 😟 | 초대 화면 | 초대 메시지 자동 생성 |
| 연결 | 남편 가입 확인 | "오 됐다" | 😀 | 연결 알림 | 즉시 알림 |
| 첫 사용 | 카드 등록 | "보안 괜찮나?" | 😟 | 카드 등록 화면 | 보안 안심 메시지 |
| 가치 경험 | 정산 화면 봄 | "이거 됐네!" | 😀 | 정산 화면 | 첫 정산 축하 |
| 재방문 | 한 달 후 다시 들어옴 | "이번 달 어땠지" | 😐 | 홈 화면 | 푸시 알림 |
| 추천 | 친구에게 공유 | "이거 진짜 좋아" | 😀 | 공유 버튼 | 추천 보상 |

이 표가 채워지면 **감정이 흐려지는 자리** (😟) 가 자기 자리를 잡습니다. 보안 걱정·남편 가입 의구심 같은 부분에서 무엇을 해야 할지가 보입니다.

## 4. 시나리오에서 발견되는 빠진 화면들

시나리오를 글로 적으면 화면 설계 단계에서 놓친 화면이 줄줄이 발견됩니다. 자주 발견되는 것들:

### 4.1 환영·온보딩 화면

가입 직후 첫 방문 시 보이는 화면. 핵심 가치·사용법을 짧게 안내.

- "둘이 같이 보는 가계부에 오신 것을 환영합니다"
- 다음 단계 안내 ("남편을 초대해 보세요")

### 4.2 빈 상태 화면

가입 직후·데이터 없을 때 (레슨 08 참고). 시나리오를 적으면 **첫 1주일은 거의 모든 화면이 빈 상태** 라는 사실이 분명해집니다.

### 4.3 동의·약관 화면

가입 시점에 약관·개인정보 동의가 필요한 경우. 의외로 자주 빠집니다.

### 4.4 권한 요청 모달

알림·위치·카메라 등의 권한을 요청하는 모달. 모바일 앱에서는 거의 필수.

### 4.5 결제 흐름

수익 모델이 결제라면 결제 화면 + 성공/실패 화면 + 영수증 화면.

### 4.6 복구 시나리오

비밀번호 분실, 계정 잠김, 데이터 복구 등. 출시 후 사용자 문의의 30%가 여기에서 옵니다.

### 4.7 푸시 알림 후 진입 화면

알림을 클릭하면 어디로 가는가. 보통 그냥 홈으로 가는 경우가 많은데, **알림이 가리키는 정확한 화면**으로 가야 합니다.

## 5. 클릭 수 줄이기 — 결정적 순간을 앞당기는 패턴

시나리오에서 결정적 순간까지의 동작 수가 많다면, 다음 패턴으로 줄일 수 있습니다.

### 패턴 1. 가입 지연 (Lazy Sign-up)

가입 없이 핵심 가치 일부를 먼저 체험하게. 가입 강제는 결정적 순간 직전에.

- 트위터: 회원 가입 전에 트윗 검색·읽기 가능.
- 인스타그램: 가입 전에 일부 게시글 미리보기.

### 패턴 2. 소셜 로그인

이메일·비밀번호 입력 대신 카카오·구글·애플 한 번 클릭. 가입 단계 5번을 1번으로 줄임.

### 패턴 3. 초기 데이터 자동 채움

페르소나가 자주 입력하는 정보를 미리 채우기. 사용자가 변경만 확인.

- 위치 자동 감지로 "강남구" 미리 채움.
- 이름·이메일을 카카오 정보에서 자동.

### 패턴 4. 단계 통합

여러 단계로 나뉜 입력을 한 화면으로 합치기. 단, 너무 많아지면 압도감이 생기므로 **3~5개 필드까지** 가 적당.

### 패턴 5. 기본값 + "나중에 설정"

처음에는 기본값으로 시작하고, "나중에 설정 가능" 안내. 사용자는 이후에 천천히 자기 취향으로 조정.

## 6. 자주 빠지는 함정

### 함정 1. Happy Path 만 그린다

"잘 풀리는" 시나리오만 그리면 출시 후 빈 상태·에러 상태에서 사용자가 길을 잃습니다. **에러 시나리오 + 비로그인 시나리오** 도 같이 그리세요.

### 함정 2. 시나리오를 바로 화면으로 그린다

화면을 먼저 그리면 흐름이 따라가기에 바쁘고, 빠진 화면을 발견 못 합니다. **글로 먼저 쓰고**, 그 글이 매끄러워지면 화면을 그리세요.

### 함정 3. 사용자의 감정을 빼고 동작만 적는다

"가입 → 카드 등록 → 정산" 처럼 동작만 적으면 함정·이탈 자리가 안 보입니다. **각 단계에서 사용자의 생각·감정**도 같이 적으세요. 여정 지도가 도움이 됩니다.

### 함정 4. 시나리오가 한 명만의 것

페르소나 1명만의 시나리오로는 충분하지 않습니다. **안티 페르소나**(우리 사용자 아닌 사람)의 시나리오도 한 번 그려 보면, 우리가 안 다루는 자리가 분명해집니다.

### 함정 5. 결정적 순간까지의 동작 수를 안 센다

세지 않으면 줄이는 동기가 없습니다. **6번 → 4번 → 3번** 으로 줄이는 작업이 곧 UX 개선입니다.

### 함정 6. 시나리오를 한 번 쓰고 안 본다

시나리오는 살아 있는 문서입니다. 출시 후 실제 사용 데이터를 보고 어디서 이탈이 일어나는지 확인한 뒤 시나리오를 갱신하세요. 갱신된 시나리오에서 다시 화면 개선.

## 7. 한 셜 더

### 7.1 Storyboarding — 영화처럼 그리기

좀 더 비주얼한 도구로 **스토리보드**가 있습니다. 만화 한 컷씩 그리듯이 사용자가 우리 서비스를 만나는 장면을 그립니다.

```
컷 1: 김지영, 출근길 지하철, 폰을 보며 검색.
컷 2: 앱스토어 화면. 우리 앱 다운로드 버튼.
컷 3: 첫 화면. "둘이 같이 보는 가계부" 카피.
컷 4: 가입 화면. 카카오 로그인 버튼.
컷 5: 초대 화면. 남편에게 코드 전송.
...
```

만화처럼 그리면 시나리오의 감정이 더 잘 살아납니다. 디자이너·개발자·이해관계자 모두에게 공유하기도 좋습니다.

### 7.2 Hook Model — 재방문을 설계

니어 일얼의 Hook Model 은 사용자가 재방문하게 만드는 4단계 사이클입니다.

> **Trigger (계기) → Action (행동) → Variable Reward (가변 보상) → Investment (투자)**

- Trigger: 푸시 알림, 친구 메시지, 외부 트리거.
- Action: 가장 단순한 행동. 인스타의 "스크롤".
- Variable Reward: 매번 다른 결과. SNS의 새 게시글, 가챠.
- Investment: 사용자가 시간·정보를 투자해 다음 트리거를 만들기. 좋아요·팔로우·게시글 작성.

이 사이클을 시나리오에 적용하면 **재방문 시나리오**가 강해집니다.

### 7.3 사용자 인터뷰로 시나리오 검증

작성한 시나리오를 잠재 사용자에게 보여주고 "이렇게 진행되면 어떨 것 같아요?" 라고 물어보세요. 답이 어색하다면 그 자리에 무엇이 빠져 있다는 신호입니다. 출시 전 5명만 인터뷰해도 시나리오의 큰 결함은 모두 잡힙니다.

### 7.4 추가 키워드

- **Service Blueprint** — 사용자 시나리오 + 백스테이지(운영자·시스템) 의 매트릭스.
- **First-Run Experience (FRE)** — 첫 방문 시점의 온보딩 설계.
- **Happy Path / Sad Path** — 잘 풀린 경로 / 막힌 경로.
- **Time-to-Value (TTV)** — 가입에서 첫 가치 경험까지 걸리는 시간.
