# 28. 수익화는 기획부터

> **한 줄 요약.** 수익 모델은 **출시 후 추가하는 부속이 아니라 기획 단계의 결정**이다. 어떤 모델인지에 따라 첫 화면·가입 흐름·데이터 수집까지 통째로 달라진다.

---

## 들어가며

길고 길었던 28편의 여정도 마지막 레슨에 도착했습니다. 신기한 점이 있습니다. 수익화는 코스의 **마지막 레슨**이지만, 그 결정은 **첫 단계인 기획**부터 시작되어야 한다는 것입니다.

레슨 02 의 사례 4 를 다시 떠올려 보세요. 학습 앱을 무료로 출시했다가 6개월 뒤 구독 모델을 붙이려 했더니 첫 화면·가입 흐름이 모두 안 맞아 사용자 70%가 결제 화면에서 이탈한 사례. 이것이 "수익화는 기획부터" 의 의미입니다.

이 레슨은 코스의 마지막 한 조각으로, 다음을 정리합니다.

- 흔한 수익 모델 5가지의 작동 원리.
- 모델별로 첫 화면·가입 흐름이 어떻게 달라지는지.
- 모델 선택의 의사결정 기준.
- 수익 모델을 검증하는 방법.
- 가격 책정의 첫 단추.

이 레슨을 다 읽으면:

- 자기 서비스에 어울리는 수익 모델을 결정할 수 있다.
- 가격을 어떻게 시작할지 안다.
- 무료 → 유료 전환의 함정을 안다.
- 수익화 지표(MRR·LTV·CAC) 를 안다.
- 코스 전체를 한 번 더 정리한다.

## 1. 핵심 개념 — 5가지 수익 모델

### 1.1 광고 모델

서비스는 무료, 사용자에게 광고 노출.

| 항목 | 내용 |
|---|---|
| **사용자 부담** | 시간·관심 |
| **수익원** | 광고주 (보통 CPM·CPC) |
| **필수 조건** | 큰 사용자 기반 (수십만~수백만) |
| **예시** | 카카오톡 채널·인스타·유튜브·뉴스 |

**작동 원리:** "사용자 = 상품, 광고주 = 고객". 사용자가 무료라고 느끼지만 사실 광고주에게 팔리는 것.

**적합한 경우:**
- 사용자 기반이 빠르게 클 가능성.
- 사용자가 매일 방문하는 서비스.
- 콘텐츠·미디어·SNS.

**함정:**
- 작은 사용자 기반에서는 수익 미미.
- 광고가 사용자 경험을 해침 → 이탈.
- 광고주 의존 (그들이 떠나면 0).

### 1.2 구독 모델 (Subscription)

매월·매년 정해진 금액. 사용자가 직접 지불.

| 항목 | 내용 |
|---|---|
| **사용자 부담** | 매월 비용 |
| **수익원** | 사용자 |
| **필수 조건** | 매달 가치를 느끼게 |
| **예시** | 넷플릭스·Notion·Spotify·SaaS 도구 |

**작동 원리:** 사용자가 "매달 이 정도 가치를 받는다" 고 느껴야 유지.

**적합한 경우:**
- 도구·콘텐츠 (반복 사용).
- B2B SaaS.
- 명확한 가치 인식.

**함정:**
- 가입은 어려움 (결제 결정).
- Churn (이탈) 관리가 핵심.
- 가치 인식 약하면 즉시 해지.

### 1.3 건당 결제 (Transactional)

사용한 만큼·구매한 만큼 결제.

| 항목 | 내용 |
|---|---|
| **사용자 부담** | 거래마다 |
| **수익원** | 사용자 |
| **예시** | 이커머스·콘텐츠 단권 판매 |

**작동 원리:** 거래 발생 시점에 가치가 명확.

**적합한 경우:**
- 물리 상품·디지털 상품 판매.
- 점유 시간 짧은 가치.

**함정:**
- 거래 빈도·단가가 모두 변수.
- 한 거래 후 다시 안 올 수도.

### 1.4 수수료 (Marketplace Fee)

플랫폼이 거래 양쪽을 연결, 수수료를 챙김.

| 항목 | 내용 |
|---|---|
| **사용자 부담** | 일부 (수수료 흡수 또는 분담) |
| **수익원** | 거래마다 일정 비율·고정액 |
| **예시** | 에어비앤비·우버·당근마켓 (일부)·배달의민족 |

**작동 원리:** 양쪽(공급자·소비자) 을 모두 모아야 함. 닭과 달걀 문제.

**적합한 경우:**
- 거래가 자연스러운 영역.
- 양쪽이 가치를 명확히 인식.

**함정:**
- 양쪽 모두 모아야 작동.
- 수수료 비율 결정의 어려움.
- 양측이 직접 연결해 우리 플랫폼을 우회.

### 1.5 프리미엄 / Freemium

기본 무료 + 고급 기능 유료.

| 항목 | 내용 |
|---|---|
| **사용자 부담** | 무료 / 일부 사용자만 유료 |
| **수익원** | 유료 사용자 |
| **예시** | Spotify·Notion·Zoom·Dropbox |

**작동 원리:** 무료로 사용자 모으고, 일부가 고급 기능에 결제.

**적합한 경우:**
- 도구·SaaS.
- 무료 가치가 분명히 있되 추가 가치도 있음.

**함정:**
- 무료가 너무 좋으면 결제 안 함.
- 무료가 너무 약하면 가입 안 함.
- 변환율(전환율) 관리가 핵심.

### 1.6 한 표 비교

| 모델 | 진입 장벽 | 수익 안정성 | 필요 규모 |
|---|---|---|---|
| 광고 | 매우 낮음 (무료) | 광고주 의존 | 매우 큼 |
| 구독 | 중간 (월 결제) | 매우 높음 | 중간 |
| 건당 | 낮음 (단발) | 변동 큼 | 작음~큼 |
| 수수료 | 낮음 | 거래 의존 | 양면 시장 |
| Freemium | 매우 낮음 (무료) | 전환율 의존 | 큼 |

## 2. 모델 선택이 첫 화면을 정한다

### 2.1 광고 모델

첫 화면 = **콘텐츠를 빨리 보여 광고 노출 기회**.
- 가입 없이도 일부 콘텐츠 가능.
- 스크롤로 광고가 자연스럽게 노출.
- 광고 차단 우회·UX 손상 균형.

### 2.2 구독 모델

첫 화면 = **무료 체험 + 가치 명확**.
- "7일 무료 체험" 같은 진입.
- 가입 → 즉시 결제 정보 수집.
- 가치 인식 가능한 미리보기.

### 2.3 건당 결제

첫 화면 = **상품·콘텐츠 둘러보기**.
- 가입 없이도 보기 가능.
- 결제 시점에 가입 강제.
- 첫 결제 후 재방문 유도.

### 2.4 수수료 (마켓플레이스)

첫 화면 = **양면 중 한 쪽에 집중**.
- 처음에는 한 쪽 (공급자 또는 소비자) 만 모음.
- 다른 쪽은 수동으로 채움.
- 양쪽 매칭이 시작되면 본격 양면.

### 2.5 Freemium

첫 화면 = **무료 사용 가치 즉시**.
- 무료로 핵심 기능 즉시 체험.
- 무료 한계에 도달하면 유료 안내 (자연스럽게).
- "고급 기능 잠금" 표시.

### 2.6 결정의 사슬

```
수익 모델 선택
   ↓
첫 화면 설계 ← 레슨 08
   ↓
가입 흐름 ← 레슨 09
   ↓
데이터 수집 항목 ← 레슨 10
   ↓
결제 시점·결제 화면
```

이 사슬이 일관되어야 사용자가 자연스럽게 흘러갑니다. 수익 모델만 바뀌면 위 모든 것이 흔들립니다.

## 3. 모델 선택 기준

### 3.1 페르소나에 어울리는가

레슨 06 의 페르소나에 비춰 결정.

- 김지영 씨가 매월 4,900원을 우리 서비스에 쓸까? → 구독 가능?
- 광고를 견디며 자주 쓸까? → 광고 가능?
- 가끔 큰 결제 한 번 할까? → 건당 가능?

페르소나의 결제 의지·빈도가 핵심.

### 3.2 가치의 성격

| 가치의 성격 | 어울리는 모델 |
|---|---|
| 매일 사용·쌓이는 가치 | 구독·광고 |
| 한 번에 큰 결정 | 건당 |
| 양쪽을 만나게 함 | 수수료 |
| 무료에 가치 + 일부 고급 | Freemium |

### 3.3 시장 표준

같은 시장의 경쟁자들이 어떤 모델인지 (레슨 04 의 시장 매트릭스). 사용자가 그 모델에 익숙하면 진입 쉬움. 다른 모델로 차별화도 가능 ("광고 없는 ◯◯").

### 3.4 LTV / CAC 가능성

- **LTV (Lifetime Value)** — 한 사용자가 평생 가져다 주는 매출.
- **CAC (Customer Acquisition Cost)** — 한 사용자 모으는 데 드는 비용.

LTV / CAC > 3 이 보통 건강. LTV 가 CAC 의 3배 이상이어야 사업이 유지.

광고 모델은 사용자당 LTV 가 작으니 CAC 도 매우 작아야. 구독 모델은 LTV 가 크니 CAC 가 클 수 있음.

## 4. 가격 책정의 첫 단추

### 4.1 가격은 가설

처음 정한 가격이 정답일 가능성은 거의 없습니다. **가설을 세우고 검증**하는 자세.

### 4.2 가격 책정 방법

**1. 비용 기반** — 우리 비용 + 마진.
- 단순. 하지만 사용자 가치 무시.

**2. 경쟁자 기반** — 경쟁자 가격 ±x%.
- 빠른 시작. 하지만 우리 가치 무시.

**3. 가치 기반** — "이 사용자가 얼마를 지불할 의향이 있는가".
- 가장 강력. 하지만 측정 어려움.

**4. 앵커링 + 단계** — 여러 티어 (Basic·Pro·Enterprise) 로 사용자가 비교하게.
- SaaS 의 표준.

처음에는 **경쟁자 기반에서 시작 + 점진 조정** 이 무난.

### 4.3 가격 단계 (Tier)

```
Free      ₩0       — 가입 유도, 핵심 가치 일부
Basic     ₩4,900   — 개인 사용자 표준
Pro       ₩9,900   — 고급 사용자
Enterprise 별도협의 — B2B
```

각 단계의 차이가 명확해야. 단계가 너무 많으면 결정 마비.

### 4.4 무료 체험 (Free Trial) vs Freemium

- **무료 체험** — 일정 기간 (7일·14일·30일) 모든 기능 무료, 이후 결제 강제.
- **Freemium** — 일부 기능 영구 무료.

무료 체험이 결제 전환율은 더 높지만, 가입 장벽도 높음 (결제 정보 미리). Freemium 은 가입 쉽지만 전환율 낮음.

### 4.5 가격은 사후 조정

처음 정한 가격을 시간이 지나며 조정. **가격 인상은 신중**:
- 기존 사용자에게 grandfathering (기존 가격 유지) 흔함.
- 새 가입자에게만 새 가격.

가격 인하는 비교적 안전. 인상은 신호·반발 관리 필요.

## 5. 수익 모델 검증

### 5.1 검증 가설

수익 모델을 결정했다면 그 자체를 가설로 본다.

가설: "월 4,900원 구독료를 결혼 1년 이내 부부의 30% 가 지불할 것이다."

검증: 1개월 데이터로 가설 vs 실제.

### 5.2 검증 도구

**1. 사전 결제 검증 (Smoke Test)**
- 출시 전 랜딩 페이지에 "월 4,900원" 표시.
- 실제 결제 정보까지 받아 보기.
- 결제 직전에 "곧 출시" 안내 + 사전 등록.

**2. 페이크 도어 테스트**
- 무료 사용자에게 결제 옵션 노출.
- 클릭률 측정.

**3. 1:1 인터뷰**
- 사용자에게 직접 가격 적정성 묻기.
- 단, 의향만 묻지 말고 과거 행동 (비슷한 도구에 얼마 썼는지).

### 5.3 핵심 지표

| 지표 | 의미 |
|---|---|
| **Conversion Rate** | 무료 → 유료 전환율 |
| **Churn Rate** | 월별 이탈율 |
| **MRR / ARR** | 월간·연간 반복 매출 |
| **LTV** | 사용자 평생 가치 |
| **CAC** | 사용자당 모집 비용 |
| **Payback Period** | CAC 회수 기간 |

이 지표들의 첫 측정 결과를 출시 1~2개월 후 점검.

## 6. 무료 → 유료 전환의 함정

### 6.1 사례의 함정

레슨 02 의 사례 4 — 무료로 시작해 6개월 뒤 구독 도입 시 70% 이탈. 이건 유명한 함정입니다.

### 6.2 안전한 도입 패턴

**옵션 A: 처음부터 유료 + 무료 체험**
- 가입 시점에 결제 정보 수집.
- 사용자가 "이건 유료 서비스" 를 인식.
- 체험 후 자동 결제.

**옵션 B: Freemium 으로 시작 + 추가 가치 유료**
- 무료 가치 충분히 좋게.
- 유료는 명확한 추가 가치.
- 기존 무료 사용자의 사용성을 해치지 않음.

**옵션 C: 광고로 시작 + 광고 제거 유료**
- 사용자가 광고를 견디는 동안 가치 인식.
- "광고 없이" 옵션 결제.

### 6.3 절대 피할 패턴

- 무료로 출시 후 갑자기 유료화. 강한 반발.
- 기존에 있던 기능을 갑자기 유료로 막음.
- 가격을 자주 바꿈.

## 7. 자주 빠지는 함정

### 함정 1. 수익 모델을 출시 후로 미룬다

가장 큰 함정. 기획·설계가 모델 가정 위에 쌓이는데 그 가정이 없으면 모든 게 흔들림.

### 함정 2. "큰 사용자 기반 후 광고로"

대부분의 서비스가 큰 사용자 기반에 도달하지 못함. 도달해도 광고만으로는 부족.

### 함정 3. 가격이 너무 낮음

"일단 싸게 해서 사용자 모으자" — 후에 인상 어려움. 가치를 명확히 한 적정 가격.

### 함정 4. 가격이 너무 높음

페르소나가 못 지불할 가격. 시장 데이터·페르소나 검증.

### 함정 5. 너무 많은 단계

10개 티어 → 결정 마비. 3~5개가 적정.

### 함정 6. Freemium 의 무료가 너무 좋음

유료로 전환할 이유 없음. 명확한 차이.

### 함정 7. 무료가 너무 약함

가입 자체가 안 됨. 충분한 핵심 가치를 무료로.

### 함정 8. Churn 무관심

신규 가입에만 집중하고 이탈 관리 안 함. 양동이의 구멍.

### 함정 9. 결제 흐름이 길음

10단계 결제 → 80% 이탈. 단순한 흐름. 카카오·애플페이.

### 함정 10. 실패한 모델 고집

3~6개월 안에 명백히 안 통하는 모델은 피벗. 매몰비용 무시.

## 8. 한 셜 더

### 8.1 PLG (Product-Led Growth)

마케팅·영업 중심이 아니라 제품 자체가 성장의 엔진. 사용자가 무료로 시작해 자연스럽게 가치를 받고, 일부가 유료로.

대표 사례: Notion·Slack·Figma. SaaS 신규 표준.

### 8.2 가격 심리학

- **₩4,900 vs ₩5,000** — 9 로 끝나는 가격이 약간 더 잘 팔림.
- **세 가지 옵션** — 가운데 옵션이 가장 많이 선택됨.
- **연간 결제 할인** — 20% 할인이면 70%가 연간 선택.
- **정렬** — 비싼 것부터 보여주면 가운데가 합리적으로 보임.

### 8.3 결제 인프라

| 도구 | 무엇 |
|---|---|
| **Stripe** | 글로벌 표준, 한국도 가능 |
| **토스페이먼츠** | 한국 |
| **이니시스·KG이니시스** | 한국 전통 |
| **나이스페이** | 한국 |
| **PayPal** | 글로벌 |
| **Apple Pay·Google Pay** | 모바일 |

처음 출시·해외 사용자 있다면 Stripe. 한국만이라면 토스페이먼츠.

### 8.4 정기 결제·환불·세금

- 정기 결제 — Stripe·토스 모두 지원.
- 환불 정책 — 명확한 약관.
- 부가세 — 한국 사업자 10%·해외 사용자는 다름.
- 매출 신고 — 사업자 등록·세무.

이 부분은 회계·법률 전문가의 도움 권장.

### 8.5 추가 키워드

- **Pricing Page Optimization** — A/B 테스트로 가격 페이지 최적화.
- **Annual Plan Discount** — 연간 결제 할인.
- **Usage-Based Pricing** — 사용량 기반 (AWS 식).
- **Enterprise Pricing** — 협의 가격 (큰 고객).
- **Acquisition Funnel** — 인지 → 가입 → 활성화 → 유지 → 결제 → 추천.
