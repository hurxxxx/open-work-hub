# 10. 데이터베이스와 저장소 선택

> **한 줄 요약.** 저장소 선택은 제품 이름을 외우는 일이 아니라, 원본 데이터와 보조 인덱스, 파일 저장소, 캐시의 역할을 구분하는 일이다.

## 오늘의 흐름

AI-Doo 업무 데이터를 어디에 두어야 하는지 판단합니다. 사용자·권한 같은 원본은 관계형 DB, 큰 파일은 객체 저장소, 검색과 벡터는 보조 인덱스로 생각합니다.

## 업무 상황

문서 파일 자체는 객체 저장소에 두고, 파일명·작성자·권한·업로드 시각은 PostgreSQL 같은 원본 DB에 둡니다. 검색을 빠르게 하려고 만든 OpenSearch나 Qdrant 인덱스는 원본이 아니라 다시 만들 수 있는 보조 저장소입니다.

## 핵심 개념 3개

| 개념 | 설명 |
| --- | --- |
| 원본 저장소 | 틀리면 안 되는 기준 데이터가 사는 곳 |
| 보조 인덱스 | 검색과 속도를 위해 원본에서 만든 복사본 |
| 객체 저장소 | PDF, 이미지, 녹음 같은 큰 파일을 보관하는 곳 |

## 작동 흐름

| 데이터 | 권장 위치 | 이유 |
| --- | --- | --- |
| 사용자, 권한, 워크스페이스 | 관계형 DB | 정확성과 관계가 중요 |
| 첨부파일, 녹음, 이미지 | 객체 저장소 | 큰 파일 전송과 보관에 적합 |
| 키워드 검색 인덱스 | Search DB | 빠른 검색과 랭킹 |
| 의미 검색 embedding | Vector DB | 유사 의미 검색 |
| 임시 작업 상태 | Redis 같은 캐시/큐 | 빠른 임시 처리 |
