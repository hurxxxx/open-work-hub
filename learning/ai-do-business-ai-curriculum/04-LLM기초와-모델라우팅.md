# 04. LLM 기초와 모델 라우팅

> **한 줄 요약.** 모델 선택은 “제일 똑똑한 모델 하나”를 고르는 일이 아니라, 데이터 등급과 업무 목적에 맞게 내부/외부 모델을 나누는 운영 정책이다.

## 오늘의 흐름

사용자 요청은 데이터 등급과 업무 유형에 따라 내부 LLM 또는 외부 API로 나뉩니다. 민감 데이터일수록 보안과 감사 기준이 먼저입니다.

## 업무 상황

공개 자료 요약은 외부 API를 써도 될 수 있습니다. 하지만 고객사 NDA 문서, 설계 변경 사유, 개인 정보가 포함된 회의록은 내부 모델이나 사내망 처리로 제한해야 합니다. 같은 “AI 질문”이라도 데이터 등급에 따라 경로가 달라집니다.

## 핵심 개념 3개

| 개념 | 설명 |
| --- | --- |
| 토큰과 컨텍스트 | 모델이 한 번에 읽고 답하는 입력·출력의 단위와 범위 |
| 모델 라우팅 | 요청을 내부 모델, 외부 API, 도구 호출 중 어디로 보낼지 정하는 규칙 |
| 데이터 등급 | 공개, 대내, 대외비, NDA 같은 보안 분류 |

## 작동 흐름

| 입력 | 판단 | 처리 | 검수 |
| --- | --- | --- | --- |
| 사용자 질문 | 데이터 등급 확인 | 내부/외부 LLM 선택 | 금지 데이터가 나가지 않았는가 |
| 첨부 문서 | 민감정보 포함 여부 확인 | 마스킹 또는 내부 처리 | 원문 보존 위치가 맞는가 |
| 긴 문서 | 컨텍스트 크기 확인 | 요약 또는 RAG 검색 | 빠진 핵심이 없는가 |
