# 바이브 코딩 학습 자료

> 비개발자가 AI와 함께 실제 AI-DO를 읽고, 수정하고, 검증하기 위한 실무형 교재입니다.

---

## 1. 이 교재의 목표

이 교재의 목표는 비개발자를 전문 개발자로 바꾸는 것이 아닙니다. 목표는 더 구체적입니다.

> 개발자 수준의 문법 암기 없이도, 실제 프로젝트에서 AI에게 일을 맡기고 결과를 검토하며 작은 변경을 안전하게 반영할 수 있는 사람을 만든다.

비개발자가 AI 코딩을 실무에 쓰려면 세 가지 역량이 필요합니다.

| 역량 | 설명 | 교재에서 다루는 방식 |
| --- | --- | --- |
| 읽기 | 코드와 폴더 구조를 보고 어디에서 무슨 일이 일어나는지 짐작하는 능력 | 시스템 구조, 도메인 구조, API 흐름을 반복해서 설명 |
| 요청 | AI에게 목표, 배경, 제약, 검증 기준을 분명히 주는 능력 | 프롬프트 템플릿과 실전 워크플로 제공 |
| 검증 | AI 결과를 그대로 믿지 않고 테스트·화면·diff로 확인하는 능력 | 검증 체크리스트와 PR 리뷰 기준 제공 |

이 세 가지가 쌓이면, 비개발자도 개발 프로젝트에서 의미 있는 역할을 할 수 있습니다.

---

## 2. 교재의 사용 방식

이 자료는 처음부터 끝까지 한 번에 외우는 책이 아닙니다. 수업에서는 핵심 장을 먼저 읽고, 기술 스택 장은 실제 작업을 만났을 때 찾아보는 방식이 좋습니다.

각 장은 가능한 한 다음 흐름을 따릅니다.

1. **왜 필요한가**
   기술 이름보다 먼저, 이 기술이 해결하는 업무 문제를 설명합니다.
2. **AI-DO에서 어디에 쓰이는가**
   실제 제품의 어느 화면, 서버, 파일 구조와 연결되는지 설명합니다.
3. **비개발자는 무엇을 봐야 하는가**
   코드 문법보다 검토 포인트, 위험 신호, 질문할 지점을 정리합니다.
4. **AI에게 어떻게 요청할 것인가**
   막연한 요청을 실무형 프롬프트로 바꾸는 방식을 보여줍니다.
5. **어떻게 검증할 것인가**
   테스트, 수동 확인, PR 리뷰에서 확인할 항목을 제공합니다.

## 3. 권장 학습 순서

### 1단계: 기본 지도 만들기

처음에는 아래 장을 순서대로 읽습니다. 이 단계의 목표는 "모든 것을 이해"가 아니라 "전체 지도를 만드는 것"입니다.

1. **01 오리엔테이션**
   AI와 함께 개발할 때 사람의 역할이 무엇인지 정리합니다.
2. **02 소프트웨어란 무엇인가**
   코드, 데이터, 실행 환경, 결과물의 관계를 이해합니다.
3. **03 프로그래밍 언어와 런타임**
   TypeScript와 Python이 왜 함께 쓰이는지 이해합니다.
4. **04 버전 관리와 Git**
   변경 이력, 커밋, 브랜치, PR의 의미를 익힙니다.
5. **06 아키텍처 기초**
   AI-DO가 어떤 구성요소로 나뉘어 있는지 봅니다.
6. **09 API와 웹 통신**
   화면과 서버가 어떻게 대화하는지 이해합니다.

### 2단계: 소프트웨어 생애주기 이해하기

AI Agent에게 구현을 맡기기 전에, 아이디어가 실제 운영 서비스가 되기까지의 흐름을 익힙니다.

1. **16 소프트웨어 생애주기**
   문제 발견부터 운영 개선까지 전체 흐름을 봅니다.
2. **17 기획과 요구사항 정의**
   막연한 요청을 문제 정의, 사용자 시나리오, 성공 기준으로 바꿉니다.
3. **18 설계와 구현 관리**
   AI Agent의 작업을 작은 PR 단위로 나누고 위험 신호를 봅니다.
4. **19 테스트 · 출시 · 운영**
   테스트 통과 이후 출시 승인, 롤백, 운영 관찰까지 연결합니다.

### 3단계: 안전하게 작업하는 법 익히기

다음 장은 실제 AI 코딩을 하기 전 반드시 읽는 것이 좋습니다.

1. **10 테스트 · 품질 · 보안**
   자동 검사와 보안 사고의 기본 개념을 잡습니다.
2. **13 검증과 테스트**
   AI가 만든 결과를 어떻게 믿을지, 무엇을 확인할지 배웁니다.
3. **14 프롬프트 워크북**
   바로 복사해 쓸 수 있는 요청 템플릿을 연습합니다.
4. **15 비개발자 보안 기초**
   시크릿, 개인정보, 권한, 운영 DB 같은 위험 요소를 익힙니다.
5. **35 바이브 코딩 실전 워크플로**
   이슈 작성부터 PR 리뷰까지 실제 작업 루프를 익힙니다.

### 4단계: AI-DO 기술 스택을 필요할 때 찾아보기

## 4. 수업 운영 예시

이 자료를 사내 교육으로 사용할 때는 다음 방식이 적합합니다.

### 1회차: 전체 지도

- 읽기: 01, 02, 06, 20
- 활동: AI-DO의 기능 하나를 골라 "화면 -> API -> DB/파일/AI" 흐름으로 그려보기
- 결과물: 내가 관심 있는 기능의 구조 추정 메모

### 2회차: 변경 안전망

- 읽기: 04, 10, 13
- 활동: 작은 PR diff를 열고 "왜 이 파일이 바뀌었는지" 설명해보기
- 결과물: 비개발자용 PR 검토 체크리스트

### 3회차: AI에게 요청하기

- 읽기: 14, 35
- 활동: 나쁜 프롬프트를 좋은 프롬프트로 바꾸기
- 결과물: 본인 업무 기능 개선 요청 프롬프트

### 4회차: 보안과 운영 책임

- 읽기: 15, 30, 33
- 활동: 시크릿, 개인정보, 권한, 운영 DB 위험 사례 토론
- 결과물: 작업 전 보안 확인 루틴

### 5회차: 소프트웨어 생애주기 종합 실습

- 읽기: 16, 17, 18, 19
- 활동: 작은 개선 아이디어 하나를 골라 문제 정의, 요구사항, PR 단위, 출시 체크리스트까지 작성
- 결과물: AI Agent에게 전달 가능한 기능 스펙과 출시 전 검토표

### 6회차 이후: 기술 스택별 실습

- 프론트 화면을 고치면 22~27
- 백엔드 API를 고치면 28~31
- AI 기능을 고치면 32, 35
- 배포나 운영을 다루면 11, 33

## 5. 이 교재에서 반복해서 묻는 질문

각 장을 읽을 때 다음 질문을 계속 반복합니다.

1. 이 기술은 어떤 문제를 해결하는가?
2. AI-DO에서는 어디에 쓰이는가?
3. 비개발자인 나는 무엇을 확인할 수 있는가?
4. AI에게 요청할 때 어떤 맥락을 줘야 하는가?
5. 변경 후 어떻게 검증해야 하는가?

이 질문에 답할 수 있으면 문법을 다 외우지 않아도 실무 협업이 가능해집니다.

## 6. 학습 완료 기준

이 교재를 끝까지 읽은 뒤 다음을 할 수 있으면 충분합니다.

- 기능 하나를 보고 관련 도메인 폴더를 대략 찾을 수 있다.
- AI에게 "고쳐 줘"가 아니라 목표, 배경, 제약, 검증 기준을 함께 줄 수 있다.
- PR diff를 보고 관련 없는 변경이나 새 의존성 추가를 질문할 수 있다.
- 테스트 통과와 실제 업무 검증이 다르다는 점을 설명할 수 있다.
- 시크릿, 개인정보, 권한, 운영 DB 변경에서 멈춰야 하는 순간을 안다.
- 기능 하나를 기획, 요구사항, 설계, 구현 관리, 테스트, 출시, 운영 관찰 흐름으로 설명할 수 있다.

이 정도가 되면 비개발자도 AI-DO 개선 과정에서 단순 요청자가 아니라 **검토 가능한 협업자**가 됩니다.

## 7. 마지막 안내

모든 장을 완벽하게 이해할 필요는 없습니다. 중요한 것은 모르는 것을 숨기지 않고, AI와 동료에게 정확히 질문하고, 위험한 변경 앞에서 멈추는 습관입니다.

이 교재는 그 습관을 만들기 위한 실무 자료입니다.
