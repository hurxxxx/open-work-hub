# Issue Tracker

Open Work Hub site work is tracked in GitLab Issues for `lumejs/open-work-hub` on
`gitlab.1punicorn.com`. GitHub is an upstream source remote, not the site issue tracker.

Use `glab` when creating, reading, or updating issues. Read-only commands such as issue list/view are
safe when requested; creating comments, labels, issues, state changes, or closures mutates external
state and requires explicit user authorization.

Durable implementation decisions should be linked from issues to the owning document under
`docs/domains`, `docs/apps`, or `docs/product`, or to an accepted ADR under root `adr/`, instead of
living only in issue comments.

Do not put secrets, runtime env values, customer data, raw logs, raw prompts, or sensitive attachments
in issue bodies, comments, or uploaded artifacts.

Every AI-generated triage or agent-brief comment should start with:

```markdown
> *This was generated by AI during triage.*
```
