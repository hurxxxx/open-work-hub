# 사용자·그룹·인사배치 계약

[ADR 0012](../../../adr/0012-company-app-access-without-workspaces.md)에 따라 한 배포는 한 회사다.
플랫폼은 사용자와 그룹, 인사배치 정보를 관리하며 업무 공간과 자원별 역할은 해당 앱이 소유한다.

## 단일 그룹과 생성 출처

`groups`가 모든 그룹의 원본이다. 조직과 연결 그룹을 각각 생성하지 않는다.
공통 속성은 이름, 설명, 활성 상태이며 생성 출처 `source`가 구성원 관리 방식을 결정한다.

| 생성 출처 | `source` | `membership_mode` | 구성원 계산 |
| --- | --- | --- | --- |
| 인사 정보 | `hr` | `hr_assignment` | 현재 주 소속이 해당 그룹인 활성·차단되지 않은 사용자 |
| 직접 생성 | `local` | `manual` | 관리자가 `group_members`에 직접 배정한 사용자 |

`membership_mode`는 서버가 출처에서 계산한 읽기 전용 속성이다. 생성 이후 출처 변경은 허용하지 않는다.
구성원 관리 방식을 바꿔 기존 배정이나 권한을 묵시적으로 변경할 수 없다.
모든 그룹은 같은 ID와 선택기를 통해 앱 사용 대상과 자원 공유에 사용한다.
그룹 생성·속성 편집·수동 구성원 관리는 플랫폼 관리자 권한을 요구한다.

## 인사 정보와 배치

인사 정보 출처 그룹에는 고유 `slug`, `unit_type`, `parent_id`, `head_user_id`,
선택적 `source_reference`가 있다. 원본 식별자는 같은 출처 내에서 유일하다.
이 정보는 그룹 속성이며 별도 조직 엔터티나 별도 관리 화면을 만들지 않는다.
인사배치·계층 검증은 API의 `domains/groups/hr.py`가 담당하며, 별도 `organization` 모듈은 두지 않는다.

- `users.primary_organization_unit_id`는 인사배치 그룹의 ID를 참조한다. 기존 필드명은
  사용자 API의 인사배치 의미를 유지하며, FK 대상은 `groups.id`다. 사번과 직책도 사용자 정보다.
- 주 소속은 하나다. 주 소속 변경은 자동 구성원과 현재 권한에 즉시 반영되며 수동 배정을 변경하지 않는다.
- 인사 그룹의 구성원 목록에 직접 추가·제거하는 요청은 서버에서 거부한다.
- 상위 그룹은 인사 정보 출처 그룹만 지정할 수 있다. 계층 순환은 거부한다.
  계층 전용 PostgreSQL 트랜잭션 잠금을 행 잠금보다 먼저 획득하고 최신 부모 관계로 검증한다.
- 하위 그룹 구성원과 책임자는 자동으로 그룹에 포함되지 않는다. 계층은 권한 상속을 만들지 않는다.
- 그룹마다 책임자 한 명을 지정하고 한 사람이 여러 그룹을 담당할 수 있다.
  책임자 지정은 인사 정보이며 구성원 자격이나 관리 권한을 부여하지 않는다.
- 그룹 비활성화는 소속과 배정 기록을 보존하며 해당 그룹을 통한 현재 권한만 제거한다.
- 직접 생성 그룹에는 인사 속성을 설정하거나 주 소속으로 배정할 수 없다. 수동 그룹 중첩은 지원하지 않는다.

계정 비활성·차단과 그룹 비활성은 현재 권한을 제거한다. 기존 비활성 구성원·앱 배정은 보존 및 제거할 수
있지만 새 비활성 주체 배정은 거부한다. 권한 계산은 PostgreSQL의 현재 값을 사용한다.

## API와 화면

- `/admin/people`: 계정·주 소속 그룹·직책·사번 및 시스템 역할 관리.
  사용자 이름과 편집 버튼으로 정보를 변경하고, 행의 그룹 관리에서 현재 배정을 확인·추가·제거한다.
  계정 생성·비밀번호 재발급의 임시 비밀번호는 별도 확인창에서만 표시한다.
  로그인 차단·삭제·비밀번호 재발급은 확인 후 실행한다.
- `/admin/groups`: 모든 그룹 검색, 출처 필터, 생성, 속성·활성 상태 편집과 구성원 확인/직접 배정.
  인사배치 그룹의 상위 그룹·책임자·원본 식별자도 같은 상세 화면에서 편집한다.
- `/admin/organization`과 `/api/v1/admin/organization-units`는 제거했다.
- `/api/v1/admin/groups`: 공통 생성·조회·편집 API. 목록은 `source=hr|local` 필터와 페이지 처리를 지원한다.
  `member_user_id`는 사용자의 저장된 직접 배정과 주 소속을 조회한다. 관리자에게만 허용하며,
  `include_inactive=true`에서는 비활성 그룹과 비활성 사용자의 기존 배정도 확인할 수 있다.
- 그룹 구성원 조회는 이름·아이디·계정 상태를 함께 제공한다. 화면에서 검색·추가·제거 후 저장한다.
  `PUT /api/v1/admin/groups/{group_id}/members/{user_id}`의 `assigned`로 사용자 하나의 배정만
  변경할 수 있다. 전체 구성원 저장과 같은 그룹 잠금·검증·감사·권한 갱신을 사용한다.
  비활성 그룹의 기존 배정은 보존·제거할 수 있지만 신규 배정은 먼저 그룹을 활성화해야 한다.
- 일반 선택기는 `/api/v1/directory/people`, `/groups`를 사용한다. 활성 대상의 검색·페이지 처리와
  제한된 IDs 조회만 제공하며 계정 상세나 보안 정보를 노출하지 않는다.
- `managed_organization_unit_ids`와 `is_department_head`는 인사 정보 표시용이며 권한 증거가 아니다.

변경 감사와 principal invalidation은 같은 변경 흐름에 포함된다. 디렉터리 검색 가능 여부와 업무 콘텐츠
접근 권한은 서로 독립적이다. 인사 그룹의 이름·slug·유형·활성 변경은 주 소속 사용자에게,
책임자·활성 변경은 이전/새 활성 책임자에게 갱신을 보낸다. 부모 변경과 변경 없는 저장은 전 직원
권한 갱신을 만들지 않는다. 수동 배정 변경은 구성원 자격이 바뀐 사용자에게만 갱신을 보낸다.

## 외부 인사 연동

현재 `hr` 출처는 서비스 내 인사 정보와 배치를 뜻한다. 실제 HR 수집 커넥터는 포함하지 않는다.
향후 수집 커넥터도 같은 그룹·사용자 변경 경계와 원본 식별자를 사용해야 하며 수동 배정을 덮어쓰지 않는다.
범위 제한 API 키와 외부 인사 조회는 [Integrations](../integrations/README.md)가 소유한다.
외부 조회의 `/integrations/directory/organization-units` 경로와 사용자 응답의
`OrganizationUnitSummaryResponse`·`primary_organization_unit_id` 이름은 현재 API 계약으로 유지한다.
이 이름들은 별도 조직 저장소를 뜻하지 않으며 인사 정보 출처 그룹을 가리킨다.

## 마이그레이션과 검증

`group_sources_20260912`는 `company_20260908` 다음 리비전이다. 기존 조직 속성을 연결된 그룹으로 옮기고
사용자의 주 소속과 상위 참조를 그룹 ID로 변환한 뒤 `organization_units`를 제거한다.
기존 그룹 ID, 수동 배정, 앱/콘텐츠 공유 참조는 유지한다. 활성 상태는 기존 조직·그룹이 모두 활성일 때만
활성으로 이전한다. 기존 조직 ID는 `source_reference`에 보존한다. 연결 그룹이 없는 조직에도 그룹을 만든다.
인사 조회 소비자는 이전 후 디렉터리를 다시 받아 그룹 ID로 참조를 갱신할 수 있으며 원본 식별자로 대조한다.

마이그레이션은 트랜잭션으로 적용한다. 이전 코드로 돌아가려면 애플리케이션 쓰기를 멈춘 상태에서
이 리비전을 downgrade한 뒤 이전 코드를 사용한다. downgrade는 조직과 주 소속 참조를 복원하며
그룹 ID와 권한 참조를 유지한다. 데이터 백업과 배포 권한은 기존 운영 절차를 따른다.

- `tests/test_company_groups.py`: 출처·자동 배정, 인사 이동, 수동 배정 보존, 권한과 책임자 정보.
- `tests/test_organization_integrations.py`: 계층·인사 검색과 외부 조회 범위.
- `tests/test_organization_concurrency_migrations.py`: 동시 계층 변경의 순환 방지.
- `tests/test_alembic_migrations.py`: 새 설치, 기존 배정/권한 보존과 downgrade/재업그레이드.
- `tests/test_company_content_boundaries.py`: 그룹 공유와 앱별 자원 권한.

임시 비밀번호 계정은 로그인·본인 확인·비밀번호 변경·로그아웃만 사용할 수 있다. 앱 입장과 일반 API,
WebSocket, 예약 작업은 비밀번호 변경 완료를 서버에서 확인한다. 관리자 비밀번호 초기화는 기존
세션을 즉시 폐기하며, 새 임시 비밀번호를 사용하는 계정에도 같은 제한을 적용한다.
